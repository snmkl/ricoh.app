## Validation limits

The macOS-owned Wi-Fi credential API is compiled into the app, but automated credential-reuse tests inject its results. Actual system/user Wi-Fi Keychain authorization prompts and reuse with a physical camera remain unverified. macOS can require authorization before returning a saved password; a saved network does not guarantee a prompt-free connection.

Location Services authorization was not available to the test bundle, so the real authorized Wi-Fi scan and network-association paths were not exercised. No live network was switched, and no physical camera was used. Those paths are implemented with CoreWLAN and covered by fakes, but should receive a real-camera check with the intended macOS permissions before relying on one-click reconnect.

Native directory and secure-password picker interactions and screen-reader announcements were not manually exercised. Folder-choice results and credential prompts are injected in lifecycle tests; the real AppKit Settings modal, a synthetic child sheet, WebKit/native bridge, bookmark persistence, filesystem writes, and app-owned Keychain adapter were exercised separately and together where applicable. Layout verification uses native window properties, WebKit geometry, and accessibility attributes rather than a visual screenshot or a screen-reader session.

The rebuilt app is in `build/GRBrowser.app`. To update the installed copy, quit it and run `./build.sh install`.
